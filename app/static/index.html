Uptime Kuma Domain API

Eine schlanke REST-API, um Domains, die dein Uptime-Kuma-Monitoring überwachen soll, aus einem externen System heraus zu pflegen — anlegen, ändern, pausieren und löschen. Jede Domain entspricht in Uptime Kuma einem HTTP(s)-Monitor.

Authentifizierung

Jeder Endpunkt außer /health erwartet einen statischen API-Key im Header X-API-Key. Der Key wird bei der Installation in der .env des Servers festgelegt.

Kopieren 
X-API-Key: dein-api-key
Fehlt der Header oder stimmt der Key nicht, antwortet die API mit 401. Betreibe die API produktiv immer hinter TLS (Reverse Proxy) — der Key ersetzt kein HTTPS.

Schnellstart

Eine Domain anlegen und die Liste aller überwachten Domains abrufen:

cURL Kopieren 
curl -X POST {{BASE_URL}}/domains \
  -H "X-API-Key: {{API_KEY}}" \
  -H "Content-Type: application/json" \
  -d '{
    "domain": "paneevino-coswig.de",
    "interval": 60
  }'

curl {{BASE_URL}}/domains \
  -H "X-API-Key: {{API_KEY}}"

GET /domains/{id} API-Key

Ruft eine einzelne Domain anhand ihrer Monitor-ID ab.

Anfrage Kopieren

  -H "X-API-Key: {{API_KEY}}"

{
  "detail": "No domain monitor with id 999."

POST /domains API-Key

Legt eine neue Domain an. Es wird ein HTTP(s)-Monitor mit url = {scheme}://{domain} in Uptime Kuma erzeugt. Nur domain ist erforderlich — alle anderen Felder haben sinnvolle Standardwerte.

Anfrage Kopieren 
curl -X POST {{BASE_URL}}/domains \
  -H "X-API-Key: {{API_KEY}}" \
  -H "Content-Type: application/json" \
  -d '{
    "domain": "bauernhof-nordheide.de",
    "name": "Bauernhof Nordheide",
    "interval": 60,
    "notification_ids": [1]
  }'
201 Created Kopieren

PUT /domains/{id} API-Key

Ändert eine bestehende Domain. Es werden nur die Felder aktualisiert, die im Body enthalten sind — alle anderen bleiben unverändert. Über active lässt sich der Monitor pausieren (false) oder fortsetzen (true).

Anfrage — pausieren & Intervall ändern Kopieren 
curl -X PUT {{BASE_URL}}/domains/24 \
  -H "X-API-Key: {{API_KEY}}" \
  -H "Content-Type: application/json" \
  -d '{
    "active": false,
    "interval": 300
  }'
200 OK Kopieren 
{
  "id": 24,

  "name": "Bauernhof Nordheide",
  "url": "https://bauernhof-nordheide.de",

  "retry_interval": 60,

DELETE /domains/{id} API-Key

Entfernt eine Domain endgültig aus Uptime Kuma — der Verlauf des Monitors geht dabei verloren.

Anfrage Kopieren 
curl -X DELETE {{BASE_URL}}/domains/24 \
  -H "X-API-Key: {{API_KEY}}"
200 OK Kopieren 
{
  "message": "Domain monitor 24 deleted."
}

Felder

Gilt für den Request-Body von POST/PUT sowie für das Response-Objekt. Bei PUT ist kein Feld Pflicht — ausgelassene Felder bleiben unverändert.

FeldTypPflicht bei POSTStandardBeschreibung
domainstringJa—Hostname ohne Schema, z. B. example.com.
namestringNeindomainAnzeigename in Uptime Kuma.
scheme"http" | "https"Nein"https"Schema, mit dem die Monitor-URL gebildet wird.
intervalint (≥ 20)Nein60Prüfintervall in Sekunden.
retry_intervalint (≥ 20)Nein60Abstand zwischen Wiederholungsversuchen in Sekunden.
max_retriesint (≥ 0)Nein0Anzahl Wiederholungen, bevor der Monitor als „down“ gilt.
resend_intervalint (≥ 0)Nein0Benachrichtigung alle N Prüfungen erneut senden, solange down (0 = deaktiviert).
upside_downboolNeinfalseStatus invertieren (erreichbar gilt als „down“).
ignore_tlsboolNeinfalseUngültige/abgelaufene TLS-Zertifikate ignorieren.
accepted_statuscodesstring[]Nein["200-299"]HTTP-Statuscode-Bereiche, die als „up“ gelten.
notification_idsint[]Nein[]IDs der Uptime-Kuma-Benachrichtigungskanäle, die bei Statusänderung ausgelöst werden.
activeboolNeintrueOb der Monitor aktiv laufen oder pausiert sein soll.
id ·nur Responseint——Monitor-ID in Uptime Kuma, wird beim Anlegen vergeben.
url ·nur Responsestring——Vollständige Monitor-URL (scheme://domain).

Fehlercodes

Alle Fehlerantworten haben die Form {"detail": "…"} (bzw. eine Liste bei Validierungsfehlern).

StatusBedeutungTypische Ursache
401UnauthorizedX-API-Key-Header fehlt oder ist falsch.
404Not FoundKeine Domain mit dieser ID, oder der Monitor ist kein HTTP(s)-Monitor.
422Unprocessable EntityUngültiger Request-Body, z. B. interval unter 20 oder scheme außerhalb von http/https.
502Bad GatewayUptime Kuma ist nicht erreichbar, oder hat die Operation abgelehnt (z. B. falsche Zugangsdaten in der Server-.env).
Beispiel — 422 Kopieren 
{
  "detail": [
    {
      "type": "greater_than_equal",
      "loc": ["body", "interval"],
      "msg": "Input should be greater than or equal to 20",
      "input": 5,
      "ctx": { "ge": 20 }
    }
  ]
}
